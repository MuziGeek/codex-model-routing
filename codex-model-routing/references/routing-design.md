# 路由设计与实现边界

## 架构

目标不是依赖 Codex 原生配置自动分配每个任务，而是建立三个互补层次：配置层只管理 Terra High 等子代理默认值，主线程和 Plan 沿用用户现有设置；`AGENTS.md` 行为层先判断拆分收益，再选择模型；运行时验收层在重新打开 Codex 后确认简单任务直做、有价值的独立任务显式派发。主线程实际模型来自当前任务，不由规则选型，也不将当前任务选择写入全局配置。

完整配置安装不设置主线程或 Plan，只把 `[agents]` 默认值设为 Terra High、最多三个并发线程。通过拆分门槛后，检索、整理、文档和机械工作选择 Luna Medium；常规实现、集成、调试和审查选择 Terra High。架构、安全、迁移、数据损失、生产风险或高度模糊的核心判断留在主线程。所有派发都需要带目标、范围、约束、验收和验证命令的任务包；覆盖模型时使用不继承父上下文的派发方式；同一文件或共享状态只保留一个写入者。

不存在 `plan_mode_model`：Plan 模式可设置推理强度，但不能通过该字段静默切换根模型。主线程也不能在配置中静默改为另一个根模型。`[agents]` 的默认值只在实际 spawn 子代理后生效，不能证明当前任务已经派发。`max` 表示推理强度上限，不等于主动派发、并行或自动升级到 Ultra。

## 路由优先级与可观察性

先尊重用户是否允许或明确要求子代理，再保留高风险核心判断，随后判断拆分收益。简单、低风险、单一目标默认直做：查一个定义、改一段说明、运行一次测试、一个逻辑变更跨几个关联文件，都不构成派发理由。“读—改—测”是工作步骤，不是独立工作项。不要为满足配额而发明复核任务；不设僵硬的文件数、步骤数或耗时阈值。

仅当工作项边界清楚、可独立验收，与主线程的有用工作能并行或值得独立复核，并且预期收益高于启动、交接与集成成本时才派发。不能确定收益则直做，遇到新的独立工作量再评估。用户明确要求子代理可免除小任务成本门槛，但不免除真实任务、安全和权限约束。高度串行耦合任务不因复杂而强拆。

通过门槛后才按工作性质选择 Luna 或 Terra；若普通调试已有明确失败证据且一次 Terra High 尝试未能解决，才可升级一次 Terra XHigh。不得因为权限、依赖或环境故障而升级模型。

实际派发前在用户可见的进度消息中记录模型、推理强度、任务边界与拆分收益；完整约束与验证命令放在任务包中。简单任务直做不增加路由宣告或固定格式汇报。派发失败必须可见，安全回退也要先声明。主线程仍须检查实际差异、父级派发参数、子代理报告和测试，不能把子代理自述当作验收。运行时验证应观察新任务的实际界面/宿主信息，不应以旧日志、PATH 指向的其他 CLI 或静态文件 hash 代替。场景决策盲测只能评估规则理解，不证明真实应用已加载规则。

## 安全写入与恢复边界

审计先于写入。脚本只触及唯一 `[agents]` 表的四个子代理字段与唯一成对的行为标记块，并保留未知 TOML、官方自定义 `[agents.<role>]` 子表和其他 AGENTS 内容。候选配置先经 `tomllib` 解析；重复或数组形式的根 `[agents]`、重复受管键、不配对或冲突标记均停止。`plan` 只输出统一 diff；`apply` 必须在当前用户明确授权后通过确认参数执行，并先生成带 SHA-256 清单的备份。

逐行编辑仅生成候选，不作为 TOML 语法正确性的依据。独立语义门槛将原解析树仅替换受管值，与候选解析树逐项比较；受管值缺失、类型错误或非受管值变化一律停止，错误输出不包含配置值。NaN 按不变值比较。带多行字符串或特殊引号的合法 TOML 若不能安全编辑，会被拒绝而非静默误写；普通多行说明可以保留。此设计不承诺编辑所有合法 TOML 布局，也不引入第三方 TOML 编辑器。

仅优化行为或保留用户当前模型时，三个命令均加 `--rules-only`（放在子命令前）：只读取、备份和更新 `AGENTS.md`。它不检查 `config.toml`，审计通过仅表示行为块符合策略，不证明配置有效；原配置缺失时也不会创建配置。完整模式会更新子代理默认值，但同样保留主模型及 Plan 字段（包括字段缺省），不会把某个型号写成全局默认。

写入使用同目录临时文件和原子替换。若写入失败，只报告备份位置，绝不自动恢复：升级可能同时迁移了未知配置，盲目回滚可能覆盖新状态。版本升级、模型可用性和配置格式都可能漂移；每次变更前重新审计，变更后重新做运行时验收。
