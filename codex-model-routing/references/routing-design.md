# 路由设计与实现边界

## 架构

目标不是依赖 Codex 原生配置自动分配每个任务，而是建立三个互补层次：配置层设定 Sol Max 主线程、Plan Max 和默认 Terra High 子代理；`AGENTS.md` 行为层要求主线程依据复杂度和风险强制显式派发；运行时验收层在重新打开 Codex 后用新的只读任务确认宿主实际加载的模型与派发结果。

配置层固定主线程 `gpt-5.6-sol` / `max`，并把 `[agents]` 默认值设为 Terra High、最多三个并发线程。行为层要求检索、整理、文档和机械任务至少派发一个 Luna Medium；要求常规多文件实现、集成、调试和审查至少派发一个 Terra High；只允许对非高风险顽固调试把 Terra 升至 XHigh 一次。架构、安全、迁移、数据损失、生产风险或高度模糊的判断留在 Sol。所有派发都需要带目标、范围、约束、验收和验证命令的任务包；覆盖模型时使用不继承父上下文的派发方式；同一文件或共享状态只保留一个写入者。

不存在 `plan_mode_model`：Plan 模式可设置推理强度，但不能通过该字段静默切换根模型。主线程也不能在配置中静默改为另一个根模型。`[agents]` 的默认值只在实际 spawn 子代理后生效，不能证明当前任务已经派发。`max` 表示推理强度上限，不等于主动派发、并行或自动升级到 Ultra。

## 路由优先级与可观察性

先按风险判断：高风险或高度模糊任务留在 Sol。其余任务再按工作性质选择 Luna 或 Terra；若普通调试已有明确失败证据且一次 Terra High 尝试未能解决，才可升级一次 Terra XHigh。不得因为权限、依赖或环境故障而升级模型。

每次显式派发前应在用户可见的进度消息中记录模型和推理强度、任务边界、选择原因、允许修改范围、验收标准、验证命令与停止条件。派发失败必须可见，不能静默退回 Sol；安全回退也要先声明。主线程仍须检查实际差异、父级派发参数、子代理报告和测试，不能把子代理自述当作验收。运行时验证应观察新任务的实际界面/宿主信息，不应以旧日志、PATH 指向的其他 CLI 或静态文件 hash 代替。

## 安全写入与恢复边界

审计先于写入。脚本只触及明确的模型字段、唯一 `[agents]` 表与唯一成对的行为标记块，并保留未知 TOML、官方自定义 `[agents.<role>]` 子表和其他 AGENTS 内容。候选配置先经 `tomllib` 解析；重复或数组形式的根 `[agents]`、重复受管键、不配对或冲突标记均停止。`plan` 只输出统一 diff；`apply` 必须在当前用户明确授权后通过确认参数执行，并先生成带 SHA-256 清单的备份。

写入使用同目录临时文件和原子替换。若写入失败，只报告备份位置，绝不自动恢复：升级可能同时迁移了未知配置，盲目回滚可能覆盖新状态。版本升级、模型可用性和配置格式都可能漂移；每次变更前重新审计，变更后重新做运行时验收。
